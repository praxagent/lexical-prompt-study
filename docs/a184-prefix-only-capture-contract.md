# A184: actual prefix-only capture contract

A184 implements and qualifies a capture-only adapter using analytical fixtures and tiny untrained causal models. It bridges a specific gap in the [A183 evidence contract](a183-matched-landmark-evidence-contract.md): A183 checks declared evidence and retained bytes, while this adapter must actually execute the declared input and observe a model's post-block residual. This is apparatus preparation, not acquisition or detector qualification. No pretrained target, real tokenizer, encoder, generation, fitting, historical corpus or held-out access is selected.

A183 remains a pinned, unchanged dependency: `landmark_evidence.py` SHA-256 `302a2a788a937a633a5bdc32a273e38fa95e0472f76bb5b7ad150ae748b3fc14`. A184 must produce completed capture metadata and bytes that its validator accepts, without relaxing A183's boundary, dtype, provenance or missingness rules. Submitted labels, censoring and prediction semantics remain A183's responsibility and are not reinterpreted by this adapter.

## Exact boundary and input

The adapter receives already prepared prompt IDs P, a declared generated-ID observation and landmark t. It neither samples nor tokenizes. P is nonempty. Count t in observed non-EOS IDs before a terminal sampled EOS, as defined for this new contract; do not reinterpret historical token counts. An EOS before t makes that landmark unavailable. EOS after t does not remove the already available boundary. At t0, the prompt alone is sufficient even if generation never occurred.

The complete model input must be exactly P followed by its first t observed non-EOS IDs. The last position is `len(P)-1` for t0 and `len(P)+t-1` otherwise. No later continuation, candidate answer, terminal EOS, invented target suffix, padding or truncation enters that capture forward. The adapter must validate token ranges, declared model dimensions and context capacity before dispatch. Unavailable or invalid inputs do not become shorter substitute captures.

The V1 available-capture path requires a CPU model in evaluation mode throughout its module tree, with strided CPU parameters/buffers, float32 floating tensors and no complex tensors. It requires four intra-op threads, little-endian host byte order and CPU autocast disabled. It rejects compiled wrappers and pre-existing model/global forward hooks rather than silently removing or accommodating them. The selected block comes from an explicitly supplied `blocks_path` resolving to a ModuleList whose length agrees with the declared geometry.

Use one batch, all-one attention, explicit sequential zero-based positions and inference-only execution. The call supplies exactly `input_ids`, `attention_mask`, `position_ids`, `past_key_values=None`, `use_cache=False` and `logits_to_keep=1`. The final setting limits retained logits; it does not append a target, score a continuation or remove prefix tokens from the forward. CPU autocast is checked at preflight and model entry; the adapter does not claim qualification of another device, precision or arbitrary custom computation inside a model. Streaming capture would require a separate qualification. The boundary state predicts the next token after the observed prefix.

Sampling a final prefix token usually does not feed that sampled token back into the model. A generation receipt therefore does not prove capture at that boundary. This separate prefix-only forward must appear in a later acquisition's call, time and memory budget; it is not a free extraction step.

## What is captured

The later scientific study must select its model and one post-block site prospectively. No site or efficacy is inherited from an earlier intervention experiment. Synthetic test sites only test adapter behavior; they are not a layer search.

Attach a single capture-only hook to the selected block's output. V1 requires a tensor of shape `[1, input_length, hidden_width]`; it does not guess a tensor from an arbitrary tuple or custom return. Observe the full post-block residual tensor and copy only the last input token's vector. The hook must not modify, replace or normalize the block output. Its source must actually have the required shape and finite float32 values; reject other actual dtypes rather than cast. Detach and defensively clone before lossless FP32 little-endian serialization, preserving the declared source device and dtype separately from storage.

Post-block residual and final-normalized hidden state are different objects. In particular, a model's final `hidden_states` entry may be after its terminal normalization. The adapter captures the block output before any subsequent terminal normalization. Reference tests must observe that exact site or explicitly account for normalization; simply matching the last exported hidden state is insufficient.

A completed capture requires exactly one expected block-hook observation within exactly one entered model forward, a successful full forward return, and successful required validation and cleanup. A hook capture followed by a later forward or adapter failure is unusable, even if the saved vector itself is finite. Do not expose it as completed evidence, select another occurrence, average captures, retry the call or fall back to another site.

## Receipts, cleanup and trust boundary

Distinguish an attempt from entry into the actual owned model forward and from a completed usable capture. Count dispatch from an owned model-entry prehook, not merely invocation of a Python wrapper or creation of a receipt. A successful available result has exactly one entry and one capture hook invocation. The adapter initiates one model call and rejects repeated entry or repeated/missing block captures; a failing exceptional model must retain actual observed counts rather than fabricate a successful single entry. The prehook runs before the model's forward body: its receipt is not proof that body computation began or completed. A failure inside the prehook can therefore count an entry without a completed forward. A blocked preflight or missing landmark does not claim a model call; a later failure after entry still records that entry.

Bind attempt, dispatch and terminal status to the observation/landmark, exact prompt and prefix identities, complete input IDs/hash/length, selected layer/site/index, attention and position arrays, cache policy, model/source declarations, tensor shape/dtype/device and retained capture bytes. Record Python/executable, Torch/Transformers versions, thread settings, device/CPU-autocast state and a memory snapshot. The reservation field is explicitly `caller_owned_not_verified`: this adapter does not acquire a reservation or certify a future study's memory budget. Retain failure/missingness evidence without fabricating a successful vector. Terminal scalar status cannot substitute for exact input and payload bindings.

Remove every owned hook on success and exceptions. Do not remove unrelated hooks or alter weights. Preserve the original failure if a subsequent cleanup/audit also fails; record the cleanup problem without replacing the primary failure. A normal-exit cleanup failure is itself a failed capture. Publication must preserve one-shot evidence and make partial files distinguishable from complete results; existing or interrupted evidence is not authorization to resume inference.

The adapter checks its actual source-file hash against the manifest and checks the actual A183 dependency file against its pinned hash. Model, tokenizer and template digests remain caller-supplied provenance declarations. Their presence does not prove the identity of loaded weights or that a native tokenizer produced the submitted IDs. The recorded model class/configuration and parameter/buffer geometry hash deliberately carry `weight_content_authenticated=False`; this is not a weight-content digest. The adapter can inspect actual call inputs, output shape/dtype, model configuration and runtime behavior in its supported interface, but a later target loader/native audit must bind actual model files, template and tokenizer to the study. The model implementation must itself be trusted and separately qualified; these guards do not establish arbitrary custom module semantics or detect malicious code. Do not turn shape agreement or an opaque hash into proof of weight identity.

## API and durable result boundary

`capture_prefix(model, *, blocks_path, manifest, observation, generation, prefix, outcome, directory)` first validates and defensively snapshots the A183 inputs and source bindings. For an available prefix it also checks model/runtime geometry before creating the attempt directory. These preflight failures create no attempt or dispatch. Once a new exclusive directory is claimed, a failure consumes it; do not reuse it as a retry destination.

An unavailable prefix is retained through A183 with capture status unavailable, no model inspection, zero dispatches and no model output. For an available prefix, successful forward completion and hook cleanup precede construction and A183 validation/publication of the completed payload. `result.json` records only `completed` or `unavailable`. A caught failure instead attempts a best-effort `failure.json` with actual counts, exception types and `capture_usable=False`, then rethrows the original exception. Failure receipt publication can itself fail; absent or partial receipts never imply success.

The return type is `CaptureResult(bundle, receipt_bytes, forward_output)`. The validated bundle and receipt are immutable evidence bytes. `forward_output` is the original opaque model return, which can contain mutable tensors; it is not authenticated retained evidence, not serialized as a detector result, and not part of the immutability guarantee. Do not expose that object through a text-only predictor or infer any scientific endpoint from its presence.

`load_capture(directory, manifest)` performs no forward. It validates the exact adapter inventory, attempt/result/dispatch bindings and the nested A183 publication. It returns the verified bundle and receipt with `forward_output=None`. A nested A183 bundle may have been created before an outer publication failure; it alone is not a completed adapter capture. Extra failure or temporary files, a missing outer result, or inconsistent counts/bindings prevent acceptance by this whole-directory loader. Completed metadata must be used as A184 evidence only after that terminal validation, not merely because a child directory is readable.

Publication inherits A183's fsynced temporary-file/exclusive-link pattern and is not atomic across multiple paths. Successful return is the writer completion boundary; in-progress file presence cannot prove durable success. A retained result accepted by `load_capture` does not prove that the original caller observed normal return, that no later failure marker was lost, or that a concurrent writer finished its final directory fsync. The loader validates the complete retained evidence, not those stronger process claims. Later acquisition accounting must separately bind normal writer return and whole-directory validation; an ambiguous publication cannot be retroactively declared successful merely because files are present. Interrupted children or uncertain final publication remain preserved, not overwritten, resumed or promoted into a successful capture by a downstream shortcut.

## Finite qualification

Qualification uses invented IDs, analytical models and deterministic untrained tiny causal models under the declared test runtime. It must establish:

- Exact t0 and positive-t input construction and last-token position; early EOS versus EOS after the landmark; caps, missing generation and invalid-range/context rejection before entry.
- Actual all-one attention, explicit positions and disabled caches at the model call; no future suffix or fabricated candidate path.
- Equality with an independently obtained direct post-block state on identical input, including the distinction at the final block before terminal normalization.
- Unchanged model outputs compared with an unhooked forward, exact hook/call counts and defensive capture bytes. Later fixture-token changes may be used in separate longer-sequence reference tests to check earlier-prefix causality; the adapter itself still receives only its requested prefix.
- Rejection of actual non-FP32, nonfinite, wrong-shape, repeated or absent captures; unusability after a post-capture failure; cleanup and original-exception preservation, with truthful entry/capture counts, including rejected repeated entries and exactly one entry on successful available capture.
- Integration of successful metadata/bytes with unchanged A183 validation and private publication, and explicit missing/failed accounting rather than fake success.

Successful tests qualify these supported adapter behaviors on the tested runtime. They do not qualify a scientific population, chosen internal representation, native prompt construction, label instrument, semantic challenger, detector calibration or transfer performance. They also do not prove that any residual contains a uniquely useful or causal feature.

A later acquisition still needs a finite population and grouped evaluation plan, actual landmark/model/site, endpoint and uncertainty policy, matched text challenger, retention plan and compute/storage limits. It must separately qualify its actual native/runtime integration and budget every generation and boundary-capture forward. A184 selects implementation, synthetic qualification and review only; no target execution, acquisition or paid service follows automatically.
