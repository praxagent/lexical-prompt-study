# A192: answer availability and conditional path ranking

This prospective finite study asks whether supplying correct answers changes conditional preference for the correct canonical answer path over one fixed arithmetic foil. It measures candidate-path probabilities. It does not measure free-generation success, prove an internal decision, validate a detector, or select an activation intervention. Closed generation studies and their outcomes remain unchanged.

## Fixed inputs and schedule

The public task namespace is `a192-answer-path-ranking-v1`. Eight fresh cores each contain two signed two-digit additions. For core indices 0–7, item indices 0–1 and operand sides 0–1, SHA256 of the ASCII string `namespace|core|item|side` determines each operand: magnitude is 10 plus the big-endian digest integer modulo 90; an odd first digest byte makes it negative. No result-dependent item selection occurs.

Each core has computed and supplied contexts. Operands, ordered correct answers and candidate paths are identical within the pair. A computed data row ends in `?`; a supplied data row ends in its correct sum. The two rows are separated by one newline, and each row uses single spaces between its left operand, right operand and answer field. Both contexts use this exact system instruction:

```text
Each of the two data rows contains a left integer, a right integer, and an answer field. If the answer field is ?, add the two integers; otherwise copy the supplied answer. Preserve row order. Output exactly two comma-separated base-10 integer answers, with no other text.
```

The two candidate texts are canonical ASCII decimal integers joined by one comma, with no spaces or positive sign. `correct` contains the ordered sums. `first_sum_plus_one` adds exactly one to the first sum and leaves the second unchanged, including when the first sum is negative. The coordinator appends the single native `<|eot_id|>` token explicitly. The candidate text itself contains no special token. No wrapper normalization, free generation, candidate search or alternate foil is used.

Core order is ascending SHA256 hex digest of `namespace|schedule|core`. Computed comes first in even core-schedule positions and supplied first in odd positions, giving four pairs in each order. The paired contexts remain contiguous. There are 16 contexts and 64 scheduled forwards. Within an even context sequence index the candidate order is correct, foil, foil, correct; within an odd index it is foil, correct, correct, foil. First occurrence is repeat 0 and second occurrence is repeat 1. Each arm has four contexts starting with each candidate. Repeats are technical checks, not additional independent cases. There are no separate technical, warmup, reference or capture forwards.

## Native construction and readout

Use the pinned Meta Llama-3.2-3B-Instruct revision `0cb88a4f764b7a12671c53f0838cd831a0843b95`, CPU FP32, eight intra-op threads and one inter-op thread, deterministic math SDPA, evaluation/inference mode, no autocast, cache, quantization or offload. Model and tokenizer assets, sources, runtime and native preparation are bound before scoring. The native template date is `24 Sep 2026`. The chat prompt must preserve the declared system/user messages, render and tokenize consistently, and contain at most 256 tokens. Each candidate target, including its one terminal EOT, must contain at most 16 tokens. The exact forward input described below must fit the model context window. Payload text must not introduce native special tokens. Any failed native guard blocks acquisition; no replacement or shorter candidate is selected.

Let P be the prompt-token sequence and T the candidate target including EOT, with length L. One fresh forward receives exactly `P + T[:-1]` and requests `logits_to_keep=L`. Its L output rows, at absolute input positions `len(P)-1` through `len(P)+L-2`, predict every token of T in order, including EOT. No EOT-input row or next-after-EOT prediction is computed. Retain all L complete finite FP32 vocabulary rows. For each row, subtract its maximum before computing the float64 sum of exponentials; subtract that log sum from the shifted chosen-token logit, then sum all token log probabilities in float64. There is no length normalization, fixed syntax-prefix conditioning, or candidate-length matching requirement. Different candidate lengths and ending probabilities remain part of the selected canonical-path endpoint. Native alignment must be qualified analytically and on an untrained tiny model before selected-model execution.

For each context/candidate, both repeated FP32 readout byte strings must be exactly identical. Repeat 0 defines its score; repeats are never averaged and no numeric tolerance is allowed. Matching readout hashes are only declarations to the pure task analyzer: the coordinator must authenticate and compare the actual bytes, their shape, inputs and provenance. Equal readout bytes must replay to exactly identical scalar scores. No mismatch is repaired by rounding, precision changes, alternate kernels or rerunning the call.

## Fixed-cohort estimand and missingness

For each context, let its margin be the correct full-path score minus the foil full-path score. A margin exists only when both candidates have two complete, finite and authenticated identical readouts. Per-candidate repeat equality is unknown until both required copies are available. Context numerical validity is false if any known repeat comparison fails, true only when both comparisons pass, and otherwise unknown. Both false and unknown validity leave the context margin unknown. Completed-call coverage and numerical validity are reported separately.

The primary is the mean of supplied margin minus computed margin across all eight fixed cores. Each core has weight 1/8. It is available only when all 16 context margins are available. If any required margin is unknown, the primary point, lower and upper values are null and its unbounded flag is true. Log-probability differences have no imposed finite missing-value bounds. No complete-case primary, imputation, confidence interval or population-level precision claim is reported. Arm means likewise require all eight contexts in that arm; missingness in the other arm does not erase an otherwise complete arm summary. Report resolved context and pair counts and positive, zero, negative and unknown margin counts.

Supplied qualification is false if any known supplied margin is less than or equal to zero, true only if all eight supplied margins are known and strictly positive, and otherwise unknown. Exact ties fail this sign criterion. A failed repeat alone leaves that margin unknown; it does not create a known nonpositive margin. A known nonpositive supplied margin dominates other unknown supplied margins. Computed-arm availability cannot change this flag. Qualification is an interpretation control and neither filters the primary cohort nor changes the schedule. A positive margin, however small, satisfies this prospectively chosen sign rule; the threshold is not a numerical error bound or significance test.

All 64 slots remain planned. Completed numeric or preference failures do not stop subsequent scoring. A hard infrastructure failure, interruption or resource stop ends the one attempt and preserves failed and unattempted slots explicitly. Missing output and orphaned files do not become valid measurements. No retry, resume, extension, candidate substitution, layer search or automatic generation experiment is authorized by the result.

## Interpretation and operational boundary

A positive resolved primary means that supplying answers increased the correct-versus-this-foil conditional margin on these eight cores and this runtime. A zero primary means no average difference in the finite cohort; a negative primary reverses the sign. None of these establishes population equivalence, internal arithmetic competence, useful free generation or a general text-versus-internal prediction advantage. The path representation and explicit ending token remain substantive measurement choices. Supplied qualification passing supports only the declared supplied-path sign control; failure or missingness constrains that interpretation without discarding the primary.

One model load and one attempt permit at most 64 causal-LM body entries; nested decoder counts are separately recorded and nonadditive. Use one bounded 12-hour resource queue, host readiness of at least 36 GiB and 64 GiB free scratch, then at most six native hours plus 60 seconds termination grace. The sampled owned-RSS ceiling is 24 GiB, available-host floor 8 GiB, raw-output ceiling 3 GiB and scratch reserve 16 GiB. These are observed stop thresholds, not resource reservations. Only owned processes may be signalled. No paid service, download fallback or different runtime is selected by a failure.

Freeze qualified public sources, tests, protocol, runtime/assets, exact inputs, private destination and code revision before acquisition. Preserve prompts, native token arrays and readouts privately; publish only permitted aggregates. A separately reviewed one-time model-free terminal audit authenticates calls and normal returns, independently reconstructs inputs and scoring, and checks fixed-cohort analysis and process cleanup. Saved artifacts do not prove an original normal writer return without its separately retained evidence.

The pure public API is `build_roster`/`validate_roster`, `build_schedule`/`validate_schedule`, and `analyze_measurements(rows, schedule, measurements)`. The latter requires all 64 positional slots, each null or exactly `{score: finite nonpositive float, logits_sha256: lowercase SHA256}`; it returns 16 context records and aggregate analysis. It does not certify native execution from those scalar declarations.
