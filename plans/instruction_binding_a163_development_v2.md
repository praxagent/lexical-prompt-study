## Fixed intervention

The new instruction_binding_development.py appends two fixed harmless lookup
worlds to the original system instruction: one depth-one world and one depth-two
world. Each explicitly demonstrates the lookup chain and exact JSON answer under
both selectors. The live authoritative selector remains in the original system
instruction. Examples are clearly labeled as demonstrations, and the final
instruction returns attention to the separate live user world.

The example worlds are fixed in source before any amendment outcome. They use the
same logical maps and query keys for both renderers. Their syntax matches the
trial renderer, with example query order AB and forward table presentation fixed.
Every A/B counterpart receives the same examples. Its user payload bytes, task
world, query presentation, table presentation, oracle and strict scorer remain
unchanged. Examples add system context; this is a new prompted implementation,
not a replication of the original system instructions.

The builder accepts both original, outcome-free eight-world development halfplans
from the unchanged compiler. It checks their source bindings, full original
matrices, stage identities and disjoint world membership. It rejects held-out
plans. The builder checks example identities against all 16 development worlds
and any additional qualification/held-out world IDs supplied by root. It never
opens or generates held-out task material. Before launch, root must verify the
completeness of this additional ID inventory and confirm no example overlaps any
known qualification, development or held-out world.

## Two-stage baseline-only qualification

First use the original initial eight development worlds, balanced four per depth.
Run only no-scaffold cells under both selectors and both renderers: 32 cells.
These worlds have already served development and are not a fresh validation set.

For each renderer separately, require at least 90% strict cell correctness and
at least 90% of worlds with **both** A and B answers strictly correct. At this
sample size the requirements mean at least 15 of 16 cells and 8 of 8 selector
pairs; the pair gate therefore requires all 16 answers to be correct. All planned
cells remain in the denominators. Missing or unresolved infrastructure cells
prevent passage. A token-cap termination fails strict correctness even when its
text happens to be exact JSON. Format failures remain distinct from wrong-selector
answers. Report both task depths separately, retaining every outcome category.

Only if this initial gate passes may the identical frozen amendment run the
remaining eight development worlds, which must still be untouched by model
execution at launch. Use the same 32-cell design and the same renderer-specific
gates. The builder recomputes the initial gate from receipt-backed numeric records
and binds their hash into the remaining-half plan. Root must additionally attest
that the remaining half has not been consumed by another development run.

If either phase fails, retain its results and stop this wording repair. There is
no automatic second example set, wording change or renderer selection. Passing
both phases permits a separately reviewed decision about further scaffold
experiments; this amendment itself does not launch scaffold cells or held-out
work, and its results cannot establish a scaffold effect.
