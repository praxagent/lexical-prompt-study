Status: operational repair, written after CPU21's dependency gate stopped and
before any Stage-B feature transformation or fit. CPU21 made no target-model
forward pass and no feature bundle. Its immutable sources, failed receipt and
teardown remain preserved. The failed check did not identify which dependency
differed; do not present an inferred NumPy mismatch as an observed fact.

## What changes

The next, separately named CPU24 allocation first runs a metadata-only runtime
qualification. Record actual Python, NumPy, Torch and Transformers versions,
the interpreter hash and the five outcome-independent projection-matrix hashes
through a strict operational schema. Save this receipt even if qualification
fails, so a failure is diagnosable without exposing logs or restricted content.
No retained generation, internal state, tensor or classifier outcome is read
during that qualification.

Python 3.12.3, the existing interpreter SHA-256, Torch 2.13.0+cu130 and
Transformers 5.14.1 remain exact requirements. NumPy may be an observed 2.x
version only if all five matrices exactly match the preallocated float64 byte
hashes generated by the frozen local NumPy 2.4.6 recipe. A seed alone is not
sufficient. No dependency installation, upgrade or fallback is permitted.

After qualification, atomically persist the exact observed runtime specification
and bind its receipt hash to this allocation's pod, source/input freeze and
execution receipt. This second freeze occurs **before reading or transforming
retained experimental artifacts**. The exporter must recheck every exact runtime
version and projection hash against that specification. This is not permission
to change versions after inspecting transformed states or fitted results.
